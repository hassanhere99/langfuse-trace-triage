## Suggested fix

Location: server behaviour of `cancel_order` (error message), plus the `order_id` schema description. The same change applies to `get_order_status` and `start_return`, which share the same `order_id` description.

Why here: the order ID format is a rule of the order tools, not a cross-tool behaviour, so it belongs in their schema and error text, not in the system prompt.

The correct format is not in the trace. Replace `<FORMAT>` and `<EXAMPLE>` with the values the server's validator accepts. If the server can accept bare numbers, normalising "10571" to the full form there is the smaller fix.

```diff
- {"error": "Invalid order_id: \"10571\""}
+ {"error": "Invalid order_id: \"10571\". order_id must look like <EXAMPLE> (<FORMAT>). Check the ID with the customer; do not tell them the order does not exist."}
```

```diff
- "order_id": {"type": "string", "description": "The order ID"}
+ "order_id": {"type": "string", "description": "The order ID, in the form <EXAMPLE>. Use exactly the form the customer gave if it matches; otherwise ask them for the full ID."}
```
