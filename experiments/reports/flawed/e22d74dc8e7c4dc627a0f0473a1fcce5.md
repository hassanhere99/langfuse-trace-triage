## Suggested fix

Location: server behaviour of `start_return` (error message), plus the descriptions of `start_return` and `cancel_order`.

Why here: the rule "returns only after shipping; cancel before that" belongs to these two tools, not to the system prompt. A recovery hint in the error is read at the moment it is needed.

```diff
 # start_return, server error for an order that has not shipped
- Order BK-10571 is not eligible for return because its status is processing.
+ Order BK-10571 is not eligible for return because its status is processing (not shipped yet). Returns are only possible after shipping. To stop this order, use cancel_order.
```

```diff
 # start_return description
- Reverse an order. Use this when the customer wants to undo a purchase and get their money back.
+ Start a return for an order that has already shipped or been delivered. Do not use for orders still processing; use cancel_order for those.

 # cancel_order description
- Undo an order. Use this when the customer wants to reverse or back out of an order they placed.
+ Cancel an order that has not shipped yet (status processing). Do not use for shipped or delivered orders; use start_return for those.
```

Whether the model should call `cancel_order` right away or first ask the customer to confirm is a product decision. The test below accepts either a `cancel_order` call or a reply that offers cancellation.
