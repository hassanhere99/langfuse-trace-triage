> result: {"error": "Order BK-10571 is not eligible for return because its status is processing."}
> final answer: "Could you please contact our customer support team to discuss possible alternatives or a refund?"

The call failed and the agent stopped. `cancel_order` was available and is the tool for backing out of an order that has not shipped. The customer got no action and a hand-off for something the agent could have done. The error text says only that the order is ineligible and names no alternative, so the tool's error message contributes.

### 2. description_overlap (confidence: medium)

Evidence:

> cancel_order: "Undo an order. Use this when the customer wants to reverse or back out of an order they placed."
> start_return: "Reverse an order. Use this when the customer wants to undo a purchase and get their money back."

Both use "undo" and "reverse" for an order, and neither says when it applies (before or after shipping). That makes the choice between them ambiguous and gives the model no signal to move from one to the other after the error. Medium because it is one trace, and because the user literally wrote "start a return", so the first call is defensible; I do not classify it as `wrong_tool`. An alternative reading is that the first call was fine and only finding 1 matters. Checking `get_order_status` first would have been the cleaner path, but nothing in the descriptions asks for it.

### 3. missing_tool_call (confidence: medium)

Evidence:

> "As per our store policy, we can only initiate returns for orders that are in the shipped or delivered state."

`get_store_policy` was never called, and the tool result contains no such rule. The "shipped or delivered" statement is not supported by anything in the trace. It may be true, but it is unverified. Medium because the claim is plausible and I cannot see the real policy text.

## Suggested fix

Location: tool descriptions of `cancel_order` and `start_return` (both), plus the error text of `start_return` (server behaviour).

Why here: the rule about which tool applies at which order status belongs to those two tools, not the system prompt.

```diff
 cancel_order description
-Undo an order. Use this when the customer wants to reverse or back out of an order they placed.
+Cancel an order that has not shipped yet (status "processing"). Use this when the customer wants to back out of an order before it ships. Do not use it for orders already shipped or delivered; use start_return for those.

 start_return description
-Reverse an order. Use this when the customer wants to undo a purchase and get their money back.
+Start a return for an order that has already shipped or been delivered, so the customer can get their money back. Do not use it for orders still processing; use cancel_order for those. If the status is unknown, call get_order_status first.

 start_return error text (server)
-Order BK-10571 is not eligible for return because its status is processing.
+Order BK-10571 is not eligible for return because its status is processing (not yet shipped). Use cancel_order instead.
```

Assumption to verify: that `cancel_order` accepts orders in `processing` status. The trace has no `cancel_order` result or policy text confirming it; check the server rules before shipping the wording.
