## Suggested fix

Location: tool descriptions of `cancel_order` and `start_return`, and the `reason` schema of `start_return`

Why here: each rule belongs to one tool, so it goes in that tool's description or schema, not in the system prompt. Both descriptions must change, because the overlap comes from the pair.

```diff
 cancel_order
-Undo an order. Use this when the customer wants to reverse or back out of an order they placed.
+Cancel an order that has NOT shipped yet (status "processing" or "paid"). Do not use for delivered orders; use start_return for those. If you do not know the order status, call get_order_status first.

 start_return
-Reverse an order. Use this when the customer wants to undo a purchase and get their money back.
+Start a return for an order that has already been delivered, so the customer can send it back for a refund. Do not use for orders that have not shipped; use cancel_order for those. If you do not know the order status, call get_order_status first.

 start_return, parameter "reason"
-Why the customer wants to return the order.
+Why the customer wants to return the order, in the customer's words. Omit this argument if the customer has not said why. Never write "None" or "N/A".
```

The status values "processing" and "paid" in the `cancel_order` text are assumptions; replace them with the ones `get_order_status` actually returns. I could not see its output in this trace.

Server side, `start_return` should also reject or drop `reason` values such as "None", so they are not stored as a real reason.
