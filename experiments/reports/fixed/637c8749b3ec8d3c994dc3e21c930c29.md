### 1. description_overlap (confidence: medium)

Evidence:

> cancel_order: "Undo an order. Use this when the customer wants to reverse or back out of an order they placed."
>
> start_return: "Reverse an order. Use this when the customer wants to undo a purchase and get their money back."

Both descriptions use the same verbs ("undo", "reverse") for the same event, and neither says when it applies (before or after shipping). The distinction only appeared in the server's error: `{"error": "Order BK-10571 has not shipped, so it can't be returned. It can be cancelled instead with cancel_order."}`. Medium rather than high: this is one trace, and the user wrote "start a return", so the model's pick was not an overlap error. I am not reporting `wrong_tool`. The user asked for a return, and `start_return` is what they asked for. I am also not reporting `tool_error_mishandled`. The error was specific, and the agent reported it accurately and did not retry or claim success.

## Suggested fix

Location: tool description of `start_return` and `cancel_order`

Why here: the rule about when each tool applies belongs to the tools themselves, not the system prompt. Change both so the model can tell them apart. The server error message is already good and needs no change.

```diff
  cancel_order
- Undo an order. Use this when the customer wants to reverse or back out of an order they placed.
+ Cancel an order that has not shipped yet. Do not use for orders that have already shipped or been delivered; use start_return for those. If unsure, check the order with get_order_status first.

  start_return
- Reverse an order. Use this when the customer wants to undo a purchase and get their money back.
+ Start a return for an order that has already shipped or been delivered, so the customer can send it back and get a refund. Do not use for an order that has not shipped; use cancel_order for those. If unsure, check the order with get_order_status first.
```

The invented shipping sentence is not worth its own fix from one trace. If it recurs, the place to address it is the tool-side wording of the cancel confirmation, not the system prompt.
