- Summary: The customer asked to "undo" an order. The agent called `cancel_order` without checking the order, which was already delivered. After the error it told the customer to contact customer service instead of calling `start_return`.

## Findings

### 1. description_overlap (confidence: high)

Evidence:

> cancel_order: "Undo an order. Use this when the customer wants to reverse or back out of an order they placed."
>
> start_return: "Reverse an order. Use this when the customer wants to undo a purchase and get their money back."

Both descriptions use the same verbs ("undo", "reverse") for the same object, and neither says when it applies (not yet shipped versus delivered). The user's word "undo" matches `cancel_order` almost literally. Neither description mentions order state or `get_order_status`.

### 2. wrong_tool (confidence: high)

Evidence:

> [user] I want to undo my order BK-10234.
> [generation 1] cancel_order {"order_id": "BK-10234"}
> [tool result] {"error": "Order BK-10234 has been delivered, so it can't be cancelled. It can be returned instead with start_return."}

The order was delivered, so `cancel_order` was the wrong tool. The agent had no way to know this without a lookup, and it did not call `get_order_status` first. This is the symptom of finding 1. The request is ambiguous between cancel and return until the order state is known.

### 3. tool_error_mishandled (confidence: medium)

Evidence:

> Tool error: "Order BK-10234 has been delivered, so it can't be cancelled. It can be returned instead with start_return."
>
> Final answer: "...you can return the item by contacting our customer service team and we will provide you with a return shipping label and instructions on how to proceed with the return. Would you like me to assist you with the return process?"

The error was specific and named `start_return`. The agent did not call it and described a customer-service process that appears in no tool result or tool description. It did tell the user the cancellation failed, so it did not claim success. The other reading is `model_error`: the error text was clear and a 3B model (`llama3.2:3b`) ignored it. I rate it medium because the trace cannot separate the two. The fix below changes `start_return`'s description, which may or may not change this behaviour for this model.

## Suggested fix

fix_location: tool_description
Location: tool description of `cancel_order` and `start_return`

Why here: The rule "cancel before shipping, return after delivery" belongs to these two tools, not to the system prompt. Change both descriptions together.

```diff
 cancel_order
-Undo an order. Use this when the customer wants to reverse or back out of an order they placed.
+Cancel an order that has not been delivered yet. Do not use it for delivered orders; use start_return for those. If you do not know the order's status, call get_order_status first.

 start_return
-Reverse an order. Use this when the customer wants to undo a purchase and get their money back.
+Start a return and refund for an order that has already been delivered. Do not use it for orders that have not shipped; use cancel_order for those. If cancel_order fails because the order was delivered, call this tool.
```
