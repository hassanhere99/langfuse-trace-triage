- Summary: The customer asked to "undo" a delivered order. The agent called `cancel_order` without checking the order, then did not use the `start_return` tool the error pointed to and told the customer to contact customer service instead.

## Findings

### 1. wrong_tool (confidence: high)

Evidence:

> User: "I want to undo my order BK-10234."
> `cancel_order {"order_id": "BK-10234"}`
> Result (ERROR): "Order BK-10234 has been delivered, so it can't be cancelled. It can be returned instead with start_return."

The order was delivered, so `cancel_order` could never succeed. A correct run looks up the order first (`get_order_status`, as the automated check expected), sees it is delivered, then uses `start_return`. The agent picked the cancel tool from the word "undo" without checking the order. The first call has no side effect here because the server refused it, but on an unshipped order the same reading would be right and on a delivered order it is wrong, so the agent has to look first.

### 2. description_overlap (confidence: medium)

Evidence:

> cancel_order: "Undo an order. Use this when the customer wants to reverse or back out of an order they placed."
> start_return: "Reverse an order. Use this when the customer wants to undo a purchase and get their money back."

Both descriptions use "undo" and "reverse" for an order, and neither names the condition that separates them (not yet shipped versus delivered) or says when not to use it. The user's word "undo" appears in the `cancel_order` description, which is the likely cause of finding 1. This is a cause for finding 1, so the fix changes both descriptions. Medium because it is one trace at temperature 0 on a 3B model: the descriptions are plainly alike, but a small model could also pick badly from better text.

### 3. tool_error_mishandled (confidence: medium)

Evidence:

> Tool result: "Order BK-10234 has been delivered, so it can't be cancelled. It can be returned instead with start_return."
> Final answer: "...you can return the item by contacting our customer service team and we will provide you with a return shipping label and instructions on how to proceed with the return. Would you like me to assist you with the return process?"

The error named the tool to use next and `start_return` was available, but the agent did not call it. It also described a process (contact customer service, receive a shipping label) that appears in no tool result in the trace. Other reading: asking the customer to confirm before starting a return is reasonable. The invented process is not, and the customer is left with no return started. The error message itself was clear, so the fix is not in it.

## Suggested fix

fix_location: tool_description
Location: tool description of `cancel_order` and `start_return`

Why here: the rule "cancel before shipping, return after delivery" belongs to these two tools, so it goes in their descriptions and not in the system prompt. The error text from `cancel_order` already says what to do and needs no change.

```diff
  cancel_order
- Undo an order. Use this when the customer wants to reverse or back out of an order they placed.
+ Cancel an order that has not shipped yet. Do not use it for an order that has been delivered; use start_return instead. If you do not know the order's status, call get_order_status first.

  start_return
- Reverse an order. Use this when the customer wants to undo a purchase and get their money back.
+ Start a return for an order that has already been delivered, so the customer can send it back and get their money back. Do not use it for an order that has not shipped; use cancel_order instead. If you do not know the order's status, call get_order_status first.
```

Finding 3 may not be fixed by these edits alone. After the diff, check whether the second test below passes. If it still fails, the next step is a regression test and possibly a different model; a system prompt line is not justified because the problem is specific to these tools.
