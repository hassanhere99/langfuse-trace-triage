## How to read this

- The ground truth is not blind. Claude drafted it from the committed traces and `demo-agent/tools.py` after reading the reports. Treat the ambiguous rows as open.
- A "fix location" is read from the report's `Location:` line. Reports name several locations in one line, so the first one named counts as primary. `server behaviour` is mapped to `error_message`. The reports have no explicit `fix_location` field yet (that is step 6), so this is a text parse and can be wrong for a phrasing it has not seen.
- The system-prompt count looks only at the `Location:` line. Reports that mention the system prompt only to say the fix does not belong there are not counted.
- Single-tool failures in the ground truth: those whose `tools_involved` has one entry and that are not clean.

## What the table does not check

Labels and locations only. Claims inside the reports are not scored. Three worth knowing before quoting a report:

- `unneeded_lookup`: the report says the empty search result "means the store does not list the book". `demo-agent/tools.py` lists Dune (stock 22); the search missed it because it matches the query as a substring of the title or the author, not both together. The trace alone cannot show this.
- `undo_delivered_order`: the report rates `wrong_tool` as medium because the trace has no order status. The order is delivered, so `start_return` was the right action.
- `cancel_shipped_order` and `return_processing_order`: the reports use `demo-agent/tools.py` as evidence, which the skill's later rule (use only the trace being triaged) no longer allows.
